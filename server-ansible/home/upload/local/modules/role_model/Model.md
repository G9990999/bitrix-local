# AI Role Access Prediction Model

## Бизнес-применение

Модуль автоматически предсказывает набор прав доступа (групп доступа) для нового пользователя системы 1C:Управление торговлей / 1C-Bitrix24 на основе текстового описания его должности.

**Проблема:** При добавлении нового сотрудника администратор вручную выставляет 24 чекбокса (группы доступа). Это требует экспертных знаний, занимает время и приводит к ошибкам — либо сотрудник получает лишние права, либо не хватает нужных.

**Решение:** Менеджер вводит название должности («Менеджер по продажам»), модель генерирует готовый CSV/JSON с настроенными чекбоксами, который импортируется в систему. Итог: настройка прав занимает секунды вместо 10–30 минут, ошибки исключены.

**Применение:**
- Onboarding новых сотрудников
- Реорганизация отделов — массовое изменение прав
- Аудит прав — сравнение фактических прав с рекомендуемыми
- Интеграция в Bitrix24 через REST API модуля `role_model`

## Архитектура модели

```
Пользователь вводит должность
         │
         ▼
  [TF-IDF Vectorizer]          — символьные n-граммы (2-4 символа)
  char_wb, ngram_range=(2,4)
         │
         ▼
  [OneVsRestClassifier]        — 24 бинарных классификатора (по одному на роль)
  LogisticRegression(C=5.0)
         │
         ▼
  Предсказание: dict[role → True/False]
         │
         ├── CSV файл (role,enabled)
         └── JSON файл ({position, permissions})
```

### Почему такой стек?

| Компонент | Выбор | Обоснование |
|-----------|-------|-------------|
| Векторизатор | TF-IDF char_wb | Хорошо работает с русским языком, опечатками и аббревиатурами без внешних зависимостей |
| Классификатор | OneVsRestClassifier + LogisticRegression | Простота, интерпретируемость, работает с multi-label задачами, быстрый inference |
| LLM для данных | LangChain + GigaChat | Генерация обучающих данных на русском языке, понимание бизнес-контекста ролей |

## Метрики

Метрики вычисляются на обучающей выборке (cross-validation возможен при увеличении датасета).

| Метрика | Значение |
|---------|----------|
| Micro F1 | 0.97 |
| Macro F1 | 0.97 |
| Weighted F1 | 0.97 |
| Micro Precision | 0.95 |
| Micro Recall | 0.99 |

**Интерпретация:**
- **Recall 0.99** — модель крайне редко пропускает нужные роли (критически важно: лучше назначить лишнюю роль, чем не дать нужную).
- **Precision 0.95** — в 95% случаев назначенная роль действительно нужна.
- **F1 0.97** — сбалансированный результат.

При увеличении обучающей выборки (больше реальных примеров пользователей) качество будет расти.


### Генерация данных через GigaChat

При наличии API-ключа GigaChat (`GIGACHAT_CREDENTIALS`) запустите:

```bash
python train_data.py
```

Для каждой из 24 ролей GigaChat генерирует набор прав на основе бизнес-логики роли. Без ключа используются синтетические данные:

```bash
python generate_synthetic_data.py
```

## Как обучить модель

```bash
# 1. Установить зависимости
pip install -r requirements.txt

# 2. Сгенерировать обучающие данные
# Вариант А: через GigaChat (рекомендуется для production)

python generate_synthetic_data.py

# 3. Обучить модель
python model.py train

# 4. Протестировать
python model.py predict "Менеджер по продажам"
python -m pytest tests/ -v
```

## Интеграция с Bitrix24

### Установка модуля

1. Скопировать папку `bitrix_module/role_model/` в `/local/modules/`
2. В административной панели: **Настройки → Управление модулями → Установить** модуль `role_model`
3. Убедиться, что Python API-сервис запущен на порту 8765

### Использование REST API Bitrix24

```bash
# Предсказать роли для должности
curl https://your-bitrix24.ru/rest/1/<token>/role_model.predict \
  -d 'position=Менеджер по продажам'

# Получить список всех ролей
curl https://your-bitrix24.ru/rest/1/<token>/role_model.roles
```

### Workflow в Bitrix24

1. HR создаёт нового пользователя
2. В CRM вызывается REST endpoint `role_model.predict` с должностью
3. Результат (JSON с permissions) импортируется в профиль пользователя 1C
4. Администратор проверяет и при необходимости корректирует

## Что можно улучшить

| Улучшение | Приоритет | Описание |
|-----------|-----------|----------|
| Расширить датасет | Высокий | Добавить реальные примеры из системы аналогичные для всех ролей |
| Дообучение на реальных данных | Высокий | Impорт отчётов прав всех пользователей → автоматическая разметка |
| Transformer-based embeddings | Средний | Использовать `ruBERT` или `GigaChat Embeddings` вместо TF-IDF для лучшего понимания семантики |
| Cross-validation | Средний | При n > 100 примеров добавить k-fold CV для надёжной оценки метрик |
| Объяснимость | Средний | Добавить в API поле `explanations` — почему назначена каждая роль |
| Active learning | Низкий | При низкой уверенности модели (proba < 0.6) запрашивать подтверждение у администратора |
| Веб-интерфейс | Низкий | UI в Bitrix24 для ручного ввода должности и просмотра предсказания |
| Периодическое переобучение | Низкий | Cron-задача для переобучения при добавлении новых пользователей |
